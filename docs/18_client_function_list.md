## 1. この資料について

新システムで提供する機能の全体像と、現在の進み具合、および残りの概算工数を一覧にしたものです。当初いただいた改善ご要望（24項目）と、7月23日にいただいた追加ご要望（20項目）の両方を機能として織り込んでいます。

### 1.1 状態の見方

| 表示 | 意味 |
|------|------|
| ✅ | できています（実際の画面でお見せできます） |
| 🔶 | 途中まで（土台はできていますが、中心部分が未完成です） |
| ⬜ | これから（未着手です） |

### 1.2 区分の見方

| 表示 | 意味 |
|------|------|
| 踏襲 | 現行システムにある機能をそのまま引き継ぎます |
| 改善 | 現行にある機能を、ご要望に沿って作り直します |
| 新規 | 現行にない機能を新しく作ります |

### 1.3 リリース段階

| 段階 | 内容 |
|------|------|
| 第1弾 | ログイン・設定・受注・献立資料・盛付指示書 |
| 第2弾 | 発注・在庫、製造・配送帳票、請求 |
| 第3弾 | 新しい業務（特別注文・試食会）、現場業務 |
| 第4弾 | AI活用（方針決定後） |

### 1.4 概算工数の見方

| 項目 | 内容 |
|------|------|
| 単位 | **人日**（1人が1日作業する量）。20人日 = 1人で約1か月 |
| 数え方 | **これから必要な残りの作業量**です。すでにできている機能（✅）は「—」と表記します |
| 含むもの | 設計・画面とサーバー処理の実装・動作テスト |
| 含まないもの | 要件の確認打ち合わせ、データ移行、社内研修、本番切替、基盤構築（§3 の末尾に別掲） |

**この数字は現時点の概算であり、確定した見積ではありません。** 現行システムのソースコードをまだ拝見できていないため、特に発注量の計算と帳票の作成ロジックは、実際の複雑さによって増減します。増減幅の大きい機能は表内に注記しています。

- **ログイン**：**パスワード再設定メール**（SMTP 設定時に送信、未設定時はログ）、**施設画面の代理閲覧**
- **受注**：**操作マニュアル PDF**、問い合わせチャット（通知連携）、注文食数の確認、受けられない注文のアラート
- **共通基盤**：Excel/CSV 生成と非同期ジョブ（処理状況画面からダウンロード）。出力ファイル先頭に**出力条件**を記録
- **発注・在庫**：発注スケジュール（業者選択・印刷・Excel 出力）、データ取込のアップロード、取込状況カレンダー、棚卸、合数ログ、食数同期、食数補正
- **請求**：単価・税率マスタ、締め（**施設グループ一括選択**・検索・プレビュー）、発行・訂正・訂正履歴、施設閲覧、**PDF（PDFKit）**
- **配送・帳票**：帳票レジストリ、製造帳票7種（仮フォーマット）、月間食数・配送ラベル・ピッキング・袋設計図（仮）、配送日プレビュー

発注量の自動計算・製造帳票の本フォーマット・取込パース本体は、現行ロジック・実ファイルの確認後に進めます。

## 5. 現行システムから無くなるもの

| 無くなるもの | 理由 |
|------------|------|
| 編集業者の選択（ログイン直後のロック取得） | 業者ロックを廃止するため不要になります。ログイン後すぐ業務画面に入れます |
| 編集可能業者の解除 | 同上。ロックが無いので解除も不要です |
| データベース管理画面 | 設定画面に機能を吸収します。チェックを通さない直接編集をなくします |
| ソーシャルログインのボタン | 現行は押しても動作していないため、実装しません |
| IPアドレス直打ち・暗号化なしの在庫システム | 基幹システムと同じドメインに統合し、通信を暗号化します |
| 二段階認証 | 今回の再構築の範囲外とします |
| アカウントロック（ログイン失敗時の自動ロック） | 運用負荷を避けるため実装しません |
