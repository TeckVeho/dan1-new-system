## FR-0xx 共通基盤

### FR-001 監査ログ

| 項目 | 内容 |
|------|------|
| 対応REQ | — (A-12) |
| 優先度 | 必須 |
| Phase | 1 |

すべてのデータ更新操作について、操作者・操作日時・対象エンティティ・変更前後の値を記録する。

- 記録対象は作成・更新・削除・論理削除・一括操作・代理操作（成り代わり）
- 変更前後の値は JSON で保持し、差分表示に利用する
- 代理操作の場合は実操作者と代理対象を両方記録する
- 監査ログ自体は更新・削除できない（追記のみ）

**受入条件**

- 任意のレコードについて「いつ誰が何を変更したか」を画面から追跡できる
- 現行の在庫システム `/update-records`（変更履歴）・`/gosu-log`（合数ログ）に相当する情報が取得できる

### FR-002 非同期ジョブ実行と進捗表示

| 項目 | 内容 |
|------|------|
| 対応REQ | REQ-22, REQ-23 |
| 優先度 | 必須 |
| Phase | 1 |

時間のかかる処理（ファイル取込・帳票生成・大量Excel出力・発注量計算）を非同期ジョブとして実行する。

- ジョブ登録時は即座に受付応答を返し、画面をブロックしない
- ジョブの状態（待機中・実行中・完了・失敗）と進捗率を画面に表示する
- 失敗時はエラー内容と再実行手段を提供する
- 同一種別・同一パラメータのジョブが実行中の場合は重複登録を防ぐ
- 完了時に通知を発行する（FR-003）

**受入条件**

- 現行で「1週間程度を目安」と制限されている食数取込が、期間制限なしで実行できる
- ジョブ実行中に他の画面操作ができる

### FR-003 通知

| 項目 | 内容 |
|------|------|
| 対応REQ | — (A-10) |
| 優先度 | 必須 |
| Phase | 1 |

システム内の出来事をユーザーに通知する。

- 通知種別: ジョブ完了・ジョブ失敗・締切リマインド・未入力アラート・他ユーザーの作業通知・データ不整合検知
- 既読/未読を管理し、未読件数をヘッダーに表示する
- 種別・期間・既読状態で絞込できる
- 一定期間経過した既読通知は自動アーカイブする（既定90日、`[要確認]`）

**受入条件**

- 現行の在庫システムで570件蓄積している通知一覧が、絞込により目的の通知に到達できる状態になる

### FR-004 ファイル管理

| 項目 | 内容 |
|------|------|
| 対応REQ | — |
| 優先度 | 必須 |
| Phase | 1 |

アップロード・生成されたファイルを一元管理する。

- アップロードは署名付きURLでストレージへ直接送信し、API サーバーを経由しない
- ダウンロードは有効期限付き署名付きURLで提供する（既定15分）
- ファイルには種別・関連エンティティ・生成日時・生成者・世代番号を付与する
- 同一種別・同一対象のファイルは世代管理し、過去世代も取得できる

**受入条件**

- 帳票・献立資料・アップロードファイルのすべてが一覧・検索・ダウンロードできる
- 認証されていない第三者がURLを推測してファイルを取得できない

### FR-005 全文検索・絞込の共通仕様

| 項目 | 内容 |
|------|------|
| 対応REQ | REQ-18, REQ-23 |
| 優先度 | 必須 |
| Phase | 1 |

一覧画面に共通の検索・絞込・並び替え機能を提供する。

- キーワード検索は対象カラムを画面ごとに定義する
- 絞込条件・並び順・表示件数は URL クエリに反映し、ブックマーク・共有できる
- 絞込条件を名前付きビューとして保存し、次回以降呼び出せる
- 並び順の変更はユーザー単位で永続化する（画面遷移後も維持）

**受入条件**

- REQ-18「並び替えても作業をすると元に戻る」が解消される
- 一覧画面の状態を URL で共有できる

### FR-006 CSV/Excel 出力の共通仕様

| 項目 | 内容 |
|------|------|
| 対応REQ | REQ-23 |
| 優先度 | 必須 |
| Phase | 2 |

一覧・帳票の出力を共通の仕組みで提供する。

- 件数が閾値（既定1,000行、`[要確認]`）を超える場合は自動的に非同期ジョブへ切り替える
- 出力形式は Excel（xlsx）と CSV を選択できる
- 出力時の絞込条件をファイル内に記録する
- 印刷用レイアウト（CSS `@media print`）を提供する

## FR-1xx 認証・権限・組織

### FR-101 ユーザー認証

| 項目 | 内容 |
|------|------|
| 対応REQ | REQ-01, — (A-01, A-02) |
| 優先度 | 必須 |
| Phase | 1 |

社内ユーザーと施設ユーザーを単一の認証基盤で認証する。

- ログインIDは社内ユーザーが社員番号、施設ユーザーが施設コード（またはメールアドレス、`[要確認]`）
- パスワードはハッシュ化して保存し、ID と同一のパスワードを禁止する
- パスワードポリシー: 最低12文字、英大小文字・数字・記号のうち3種以上（`[要確認]`）
- 初回ログイン時にパスワード変更を強制する
- ログイン失敗5回で15分間ロックする
- セッションは一定時間で失効する（社内8時間・施設24時間、`[要確認]`）

**受入条件**

- 現行の「パスワード = ログインID」の運用が廃止される
- 単一ドメイン・HTTPS でログインでき、2システム間のリダイレクトが発生しない

### FR-102 多要素認証（社内ユーザー）

| 項目 | 内容 |
|------|------|
| 対応REQ | — (A-01) |
| 優先度 | 推奨 |
| Phase | 1 |

社内ユーザーに TOTP による多要素認証を提供する。管理者権限を持つユーザーには必須とする。

### FR-103 HACCP番号の管理

| 項目 | 内容 |
|------|------|
| 対応REQ | — (A-02) |
| 優先度 | 必須 |
| Phase | 1 |

社内ユーザーに HACCP アプリの番号を属性として保持する。

- 社員番号（6桁）と HACCP番号（5桁）を対応付けて管理する
- ログインIDは社員番号とし、HACCP番号でもログインできるようにする（別名ログイン）
- 画面ヘッダーに `【社員番号】氏名` を表示する（現行踏襲）
- 帳票・操作履歴に HACCP番号を併記する

**受入条件**

- 現場が認識している HACCP番号（00020 等）でログインできる
- 誰が発注・在庫管理を行ったかを HACCP番号で追跡できる

### FR-104 ロールと権限

| 項目 | 内容 |
|------|------|
| 対応REQ | — |
| 優先度 | 必須 |
| Phase | 1 |

ロールベースの権限管理を提供する。詳細は `10_auth_roles.md`。

- ロール: システム管理者 / 社内管理者 / 社内一般 / 施設管理者 / 施設一般
- 権限は機能単位（画面の閲覧・作成・更新・削除・出力・承認）で定義する
- ロールに対する権限割当を画面から変更できる
- 社内一般ユーザーの操作可能範囲（担当業者・担当施設）を個別に設定できる

**受入条件**

- 現行の「管理者 / 一般社員」の権限差分（編集業者解除の可否、ユーザーマスタ新規作成の可否）が再現される
- Django Admin 相当の無制限データ編集画面を持たない

### FR-105 施設ユーザーへの成り代わり

| 項目 | 内容 |
|------|------|
| 対応REQ | REQ-03 |
| 優先度 | 必須 |
| Phase | 2 |

社内管理者が施設ユーザーの画面を代理で閲覧・操作できる。

- 対象施設を選択して施設ビューに切り替える
- 成り代わり中は画面上部に警告バーを常時表示する
- 成り代わり中の操作はすべて監査ログに「代理操作」として実操作者と共に記録する
- 権限設定により「閲覧のみ」「操作可」を切り替えられる

**受入条件**

- 施設に請求書が正しく発行されているかを社内から確認できる
- 施設の注文入力を社内が代行できる（電話注文の代理入力）

### FR-106 組織・施設・ユニット管理

| 項目 | 内容 |
|------|------|
| 対応REQ | REQ-10 |
| 優先度 | 必須 |
| Phase | 1 |

施設（顧客）とその配下のユニットを管理する。

- 施設は契約開始日・契約終了日を持ち、期間で有効性を判定する
- ユニットは施設に属し、表示順・配送情報・食種を持つ
- 施設の登録・変更を単一の画面で完結させる（現行は複数マスタ画面に分散）
- 施設に紐づく設定（食種・アレルギー・単価・参照ロジック・資料フォルダ・製造パターン）を1画面のタブで編集できる
- 登録後にすべての項目を変更できる

**受入条件**

- REQ-10「新規施設登録の際の内容修正」が単一画面で完結する
- 施設361件を検索・絞込して目的の施設に到達できる

## FR-2xx マスタ管理

マスタ管理の詳細仕様は `06_master_management_spec.md` を参照。ここでは要件のみ定義する。

### FR-201 マスタ共通仕様

| 項目 | 内容 |
|------|------|
| 対応REQ | REQ-02 |
| 優先度 | 必須 |
| Phase | 1 |

すべてのマスタに共通の操作を提供する。

- 一覧（検索・絞込・並び替え・表示件数変更）、作成、更新、論理削除、復元
- 論理削除したレコードは既定で非表示とし、参照している既存データは影響を受けない
- 表示順（`sort_order`）をドラッグ操作で変更でき、変更は即時保存される
- 変更履歴を監査ログで追跡できる
- CSV による一括インポート・エクスポート

**受入条件**

- 現行 Django Admin（15モデル）で行っていた操作がすべてマスタ画面で完結する
- マスタ変更に開発者の介入が不要になる

### FR-202 有効期間を持つ設定

| 項目 | 内容 |
|------|------|
| 対応REQ | REQ-11, REQ-16, REQ-17 |
| 優先度 | 必須 |
| Phase | 1 |

業務日付によって値が変わる設定に有効期間（`valid_from` / `valid_to`）を持たせる。

対象: 施設の食種、施設のアレルギー設定、単価、税率、製造パターンの割当、参照ロジックの割当、資料出力ルール

- 設定変更時は既存レコードを書き換えず、新しい有効期間のレコードを追加する
- 特定日時点の設定を解決する共通ロジックを提供する
- 同一対象の有効期間が重複しないことをバリデーションで保証する
- 「いつから適用するか」を指定して未来日付の変更を予約できる

**受入条件**

- 食種を変更しても、変更日より前の喫食日を対象とする資料・帳票の内容が変わらない（REQ-16）
- 過去の任意日時点の設定内容を画面から確認できる

### FR-203 嚥下食区分マスタ

| 項目 | 内容 |
|------|------|
| 対応REQ | REQ-07, REQ-09 |
| 優先度 | 必須 |
| Phase | 1 |

嚥下食の区分を独立したマスタとして管理する。

- 区分（ソフト食・ミキサー食・ゼリー食など）を任意に追加・削除できる
- 表示順を設定でき、注文画面・帳票・資料のすべてで同一の並び順が適用される
- 初期の並び順は ソフト食 → ミキサー食 → ゼリー食 とする
- 区分を追加すると、注文入力画面の入力列が自動的に増える

**受入条件**

- REQ-07 の並び順が全画面で一致する
- REQ-09「嚥下食が追加になった際の欄の追加」が開発者依頼なしで完了する

### FR-204 製造パターン・集荷日・着日マスタ

| 項目 | 内容 |
|------|------|
| 対応REQ | REQ-08 |
| 優先度 | 必須 |
| Phase | 4 |

製造日を起点とした集荷日・着日のオフセットをパターンとして管理する。

- パターンは集荷オフセット（D0〜D3）と着荷オフセット（D1〜D3）の組み合わせで定義する
- パターンに名称・適用条件（地域・配送業者・施設グループ）を設定できる
- 施設またはユニットにパターンを割り当てる（有効期間付き）
- 祝日・休業日を考慮した実日付の算出ロジックを持つ
- パターン変更時、影響を受ける将来の配送予定を一覧で確認できる

**受入条件**

- 集荷日・着日のパターン変更が画面から完結する
- 変更が過去の配送実績に遡及しない

### FR-205 締切ルールマスタ

| 項目 | 内容 |
|------|------|
| 対応REQ | REQ-13 |
| 優先度 | 必須 |
| Phase | 2 |

注文の締切を設定として管理する。

- 締切ルールは対象注文種別ごとに定義する（仮注文・食数変更・合数・アレルギー・元旦注文・特別注文）
- 締切は「喫食日の N 日前の指定曜日 HH:MM」または「喫食日の N 日前 HH:MM」で定義する
- 既定値の初期設定は現行相当の 17:00 とする
- 施設グループ単位・施設単位の個別締切を設定できる（優先順位: 施設 > グループ > 全体）
- 例外日（正月・長期休暇など）を登録して締切を前倒し・延長できる
- 例外日は繰り返し設定（毎年1月1日など）も可能とする

**受入条件**

- 正月の仮注文前倒しが社内担当者の操作のみで完結し、開発者依頼が不要になる（REQ-13）
- 締切時刻を画面から変更できる

### FR-206 締切の表示

| 項目 | 内容 |
|------|------|
| 対応REQ | REQ-13 |
| 優先度 | 必須 |
| Phase | 2 |

締切情報を施設ユーザーが常に把握できるよう表示する。

- 全注文画面に「次回締切: M月D日(曜) HH:MM（残り N日 N時間）」を表示する
- 締切1時間前を切ると強調表示に切り替える
- 対象喫食日ごとの締切一覧をカレンダー形式で表示する
- 締切超過後は入力欄を非活性にし、理由を明示する
- 締切変更時は対象施設へ通知を発行する

**受入条件**

- REQ-13「何日（何曜日）の何時に締め切るという情報が画面に出ていた方が良い」を満たす

### FR-207 献立定型文マスタ

| 項目 | 内容 |
|------|------|
| 対応REQ | REQ-18 |
| 優先度 | 必須 |
| Phase | 3 |

盛付指示書の定型文を管理する。

- 一覧に本文のプレビュー（先頭N文字）を表示し、クリックせずに内容が分かる
- 本文の全文検索、カテゴリ・タグ・対象区分（基本食用 / 嚥下用）による絞込
- 並び順の変更が永続化される（FR-005）
- 定型文ごとに使用回数と最終使用日を表示する
- 本文の類似度が高いレコードを重複候補として検出し、統合を提案する
- 一定期間未使用の定型文を一括アーカイブできる
- アーカイブしても過去の盛付指示書の内容は変わらない

**受入条件**

- REQ-18 の4課題（内容が見えない・並び替えが戻る・検索できない・整理できない）すべてが解消する

### FR-208 アレルギーマスタと施設別設定

| 項目 | 内容 |
|------|------|
| 対応REQ | REQ-12 |
| 優先度 | 必須 |
| Phase | 2 |

アレルギー種類と施設ごとのアレルギー設定を管理する。

- アレルギー種類マスタ（頻発フラグ付き）
- 施設別アレルギー設定を追加・**削除**できる
- 削除は論理削除とし、過去の注文・帳票データへは影響しない
- 削除時に影響範囲（未確定の将来注文の件数）を警告表示する
- 誤登録の削除操作を監査ログに記録する

**受入条件**

- REQ-12「施設のアレルギー消去（間違えて登録したりもするので）」が画面から実行できる

### FR-209 資料出力ルールマスタ

| 項目 | 内容 |
|------|------|
| 対応REQ | REQ-11 |
| 優先度 | 必須 |
| Phase | 3 |

施設の食種と出力すべき資料の対応をルールとして管理する。

- 食種（常食・薄味・汁無し・嚥下各種など）ごとに出力対象の資料種別を定義する
- 施設に食種を割り当てると、対応する資料が自動的に出力対象になる
- ルールは有効期間を持ち、変更が過去の資料に遡及しない（FR-202）
- 施設単位の個別上書き設定を許容する

**受入条件**

- REQ-11「施設食種の変更に伴う資料出力の設定」が画面から完結する
- 食種変更時に資料の出力対象が自動的に切り替わる

## FR-9xx 新規機能

### FR-901 特別注文枠（おせち容器注文を含む）

| 項目 | 内容 |
|------|------|
| 対応REQ | REQ-19 |
| 優先度 | 必須 |
| Phase | 7 |

期間限定の注文枠を作成し、施設からの注文を受け付ける。

- 社内が注文枠を作成する（商品名・単位・単価・受付期間・対象施設・上限数）
- 受付期間中のみ施設ポータルに注文欄が表示される
- 施設は数量を入力して注文する
- 社内は注文を集計し、Excel 出力できる
- 締切はマスタで設定する（FR-205）
- おせち容器注文はこの枠組みの一適用例として運用する

**受入条件**

- REQ-19「必要に合わせて注文欄が出せるような仕様」が満たされ、FAX 運用を廃止できる

### FR-902 試食会対応

| 項目 | 内容 |
|------|------|
| 対応REQ | REQ-24 |
| 優先度 | 必須 |
| Phase | 7 |

試食会向けの食事を通常注文と区別して管理する。

- 試食会を登録する（開催日・開催場所・対象・喫食日・食数）
- 注文に区分（通常 / 試食会 / 特別注文）を持たせる
- 帳票への連携可否を注文区分ごとにマスタで制御する
  - **連携する**: 食数集計表、調理表、計量表、盛付指示書、ピッキング指示書
  - **連携しない**: 佐川伝票、配送ラベル、請求データ、売価計算
- 試食会の実績を一覧・集計できる

**受入条件**

- REQ-24「佐川急便及び売上データに紐づけない。製造関係の帳票のデータは紐づける」が満たされる
- 試食会分が請求・売上データに混入しない
