# 14. 未決事項・確認事項

作成日: 2026-08-04

各ドキュメントの `[要確認]` を集約した。要件定義の合意前に確認すべき項目である。

**優先度の定義**

| 優先度 | 意味 |
|-------|------|
| **S** | 確認できないと設計を確定できない。最優先 |
| A | 設計に影響する。Phase 開始前に必要 |
| B | 実装時に必要。並行して確認可能 |
| C | 運用開始までに決めれば足りる |

## 6. 確認の進め方（提案）

### 6.1 第1回打ち合わせ（優先度S）

Q-01〜Q-04 を扱う。ソースコードとDBの提供可否が決まらないと、以降の精度が上がらない。

| 議題 | 目的 |
|------|------|
| ソースコード・DBスキーマの提供 | Q-01, Q-02 |
| 食種マスタの所在 | Q-03 |
| `/order/` の500エラー | Q-04 |
| 現行不具合の報告 | I-01〜I-04 |

### 6.2 第2回打ち合わせ（業務ルール）

Q-05〜Q-15 を扱う。業務担当者（受注・製造・配送・請求の各担当）の参加が必要。

| 議題 | 参加者 |
|------|--------|
| 嚥下食・食種・資料出力の対応 | 献立・資料担当 |
| 製造パターン（D0〜D3） | 製造・配送担当 |
| 締切ルールの全量 | 受注担当 |
| 参照ロジック | 発注担当 |
| 試食会・おせち容器の運用 | 営業・受注担当 |

### 6.3 第3回打ち合わせ（外部連携・インフラ）

Q-16〜Q-32 を扱う。佐川急便・ラベル機器・らくらく献立の実物確認を含む。

| 議題 | 準備物 |
